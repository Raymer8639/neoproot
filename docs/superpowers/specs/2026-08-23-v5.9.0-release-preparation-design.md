# v5.9.0 release preparation design

## Goal

Publish the unreleased compatibility and performance work after the release
notes and CI prove the portable and release builds retain their intended
behavior.

## Release scope

`v5.9.0` contains every change after `v5.8.0`:

- the opt-in `--link2symlink-dirent` feature;
- restored `HAVE_PROCESS_VM` build detection;
- bwrap covered-binding and inherited `/proc` mountinfo compatibility fixes;
- startup rejection when neoproot is already traced by an outer PRoot.

The opt-in directory-entry feature is backward compatible but new public
functionality, so this is a minor release rather than a `v5.8.1` patch.

## CI design

The existing workflow builds both release and portable modes. In each matrix
job it will continue to compile the existing test programs and run
`basic_test.sh` and `advanced_test.sh`. Those two scripts will use `set -e`,
so any failing neoproot invocation becomes a failing CI step instead of merely
printing a failure message.

Three deterministic scripts will run as separate CI commands after the basic
and advanced smoke tests:

1. `test-process-vm-build.sh` rebuilds neoproot and requires `--version` to
   report `process_vm = yes`.
2. `test-bwrap-oldroot-bind.sh` checks that a covered `/tmp` binding survives
   the bwrap-style pivot/oldroot path.
3. `test-tracer-guard.sh` creates a traced child and requires the startup
   rejection and Termux-host guidance.

`test-bwrap-proc-dirfd.sh` intentionally remains outside GitHub CI. Its
mountinfo assertion requires a Termux `/data` root and exits successfully with
a documented skip elsewhere. The existing Termux deterministic probe and the
actual Codex sandbox smoke remain the release-environment validation for that
path.

## Documentation and release flow

`CHANGELOG.md` receives a dated `v5.9.0` section describing the above
user-visible compatibility, safety, and test changes. No version constant is
maintained in the source tree; the annotated Git tag is the release version.

The pushed `fix/process-vm-build-detection` branch will receive these release
preparation commits, then open a PR to `master`. The PR must pass both ARM64
CI build modes before merge. After merge, `master` is tagged `v5.9.0`; the
existing tag-triggered workflow builds and publishes the `neoproot` and
`neoproot-portable` release assets.

## Verification

Before opening the PR, build neoproot with the documented local talloc paths,
compile the test programs, run the three portable CI regression scripts where
the host environment permits, and inspect `git diff --check`. The PR CI is
the required independent verification of both release modes. The tag is not
created until that PR is merged with green checks.
